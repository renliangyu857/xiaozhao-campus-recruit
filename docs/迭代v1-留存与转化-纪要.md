## 二、实现要点

### 方案9
- **配置**：`application.yml` 增加 `app.trial-vip-days: 2`（0 表示不自动开通）。
- **逻辑**：`AuthService.createUser` 保存用户后调用 `grantTrialVip(userId)`，插入 `user_member`（plan_id=`trial`，end_at=now+2 天）。
- **前端**：`UserDto.isTrial`、VIP 页根据 `isTrial` 展示「体验会员」。

### 方案7
- **接口**：`GET /api/vip/dashboard` 返回 isVip、planId、isTrial、vipExpiry、referralCodeCount、savedQueryCount。
- **前端**：VIP 页拉取 dashboard，展示「体验会员」/「尊贵的 VIP 会员」及「内推码库共 X 个热门公司」（X>0 时）。

### 方案6
- **表**：`referral_code`（company_name, code, contributor_id, usage_count, is_valid, created_at）。
- **接口**：`GET /api/referral-codes` 分页列表（可选 companyName）；`POST /api/referral-codes/{id}/use` 记录使用。均需登录且 VIP，否则 403。
- **前端**：内推码页（仅 VIP 显示导航入口），列表、按公司筛选、复制、标记已用。

### 方案3
- **表**：`user_invitation`（inviter_id, invitee_id, invite_code, reward_status）。
- **逻辑**：生成时插入 invite_code、inviter_id、reward_status=pending；绑定时代入 invitee_id，双方各 +3 次 bonus_queries；邀请满 3 人/10 人给邀请者 5 天/30 天 VIP（plan_id=promo）。
- **用户**：`app_user` 增加 `bonus_queries`；查询扣减时优先扣 bonus，再扣每日免费次数。
- **接口**：POST `/invite/generate`、GET `/invite/stats`、POST `/invite/bind`（body.inviteCode）。
- **前端**：邀请页（生成链接、复制、统计）；首屏或登录后若 URL 带 inviteCode 则写入 sessionStorage，登录成功后调 bind。

## 五、表结构变更 SQL

以下为本次迭代涉及的表结构变更，便于手工迁移或与 JPA `ddl-auto` 对照。若使用 `ddl-auto: update`，Hibernate 会自动建表/加列，仍建议在重要环境用脚本留存。

**你当前使用 Supabase（PostgreSQL），请执行下方「PostgreSQL / Supabase」脚本；MySQL 仅作参考。**

### 5.1 PostgreSQL / Supabase（推荐）

与项目内 `backend/supabase-schema.sql` 风格一致，可直接在 Supabase SQL Editor 中执行。

```sql
-- 已有表变更：app_user 增加邀请奖励用「额外查询次数」
ALTER TABLE app_user
  ADD COLUMN IF NOT EXISTS bonus_queries INTEGER NOT NULL DEFAULT 0;

-- 内推码库（方案6）
CREATE TABLE IF NOT EXISTS referral_code (
    id              BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    company_name    VARCHAR(128) NOT NULL,
    code            VARCHAR(128) NOT NULL,
    contributor_id  BIGINT,
    usage_count     INTEGER NOT NULL DEFAULT 0,
    is_valid        BOOLEAN NOT NULL DEFAULT true,
    created_at      TIMESTAMP NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_rc_company ON referral_code (company_name);
CREATE INDEX IF NOT EXISTS idx_rc_valid ON referral_code (is_valid);

-- 邀请关系（方案3）
CREATE TABLE IF NOT EXISTS user_invitation (
    id            BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    inviter_id    BIGINT       NOT NULL,
    invitee_id    BIGINT,
    invite_code   VARCHAR(64)  NOT NULL,
    reward_status VARCHAR(32)  NOT NULL DEFAULT 'pending',
    created_at    TIMESTAMP    NOT NULL,
    CONSTRAINT uk_ui_invite_code UNIQUE (invite_code)
);
CREATE INDEX IF NOT EXISTS idx_ui_inviter ON user_invitation (inviter_id);
CREATE INDEX IF NOT EXISTS idx_ui_invitee ON user_invitation (invitee_id);
```

说明：`user_member` 表结构未改，仅约定 `plan_id` 新增取值 `trial`（体验）、`promo`（邀请奖励等）。若 `app_user` 已由 JPA 自动加过 `bonus_queries`，可跳过 ALTER，或使用 `ADD COLUMN IF NOT EXISTS`（PostgreSQL 9.5+）。

### 5.2 MySQL（仅作参考）

```sql
-- 已有表变更
ALTER TABLE app_user
  ADD COLUMN bonus_queries INT NOT NULL DEFAULT 0 COMMENT '邀请等奖励的额外查询次数';

-- 内推码库（方案6）
CREATE TABLE referral_code (
  id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  company_name VARCHAR(128) NOT NULL,
  code VARCHAR(128) NOT NULL,
  contributor_id BIGINT NULL,
  usage_count INT NOT NULL DEFAULT 0,
  is_valid TINYINT(1) NOT NULL DEFAULT 1,
  created_at DATETIME(6) NOT NULL,
  INDEX idx_rc_company (company_name),
  INDEX idx_rc_valid (is_valid)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 邀请关系（方案3）
CREATE TABLE user_invitation (
  id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  inviter_id BIGINT NOT NULL,
  invitee_id BIGINT NULL,
  invite_code VARCHAR(64) NOT NULL,
  reward_status VARCHAR(32) NOT NULL DEFAULT 'pending',
  created_at DATETIME(6) NOT NULL,
  INDEX idx_ui_inviter (inviter_id),
  INDEX idx_ui_invitee (invitee_id),
  UNIQUE KEY uk_ui_invite_code (invite_code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```
