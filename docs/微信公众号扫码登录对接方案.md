## 一、前置条件准备

### 1. 公众号类型确认

- 登录 `mp.weixin.qq.com`
- 在「设置与开发 → 公众号设置 → 基本设置」确认类型为：
  - ✅ **服务号（已认证）**  
- ⚠️ 如果是订阅号：大部分网页授权能力受限，不建议做 PC 扫码登录。

### 2. 域名与 HTTPS 准备

- 为你的服务选定正式域名，例如：
  - 前端：`https://jobhub.cn`
  - 后端：`https://jobhub.cn/api`
- 要求：
  - **已备案**
  - 全站 **HTTPS**（证书正常）

### 3. 后端必须能被公网访问

- 部署 Spring Boot 到一台能访问公网的服务器
- 推荐结构：
  - Nginx 监听 `443` → 反向代理到 Spring Boot（`8080`）
  - Nginx 上配置 `server_name jobhub.cn;`，并把 `/api` 转到 Spring Boot

## 二、在微信公众平台的配置

登录公众号后台 `mp.weixin.qq.com`，按下面几步配置。

### 1. 获取 AppID / AppSecret

**路径**：**开发 → 基本配置**

- 记录：
  - 开发者ID（**AppID**）：`wx1234567890abcdef`
  - 开发者密码（**AppSecret**）：`xxxxxxxxxxxxxxxxxxxxxxxxx`
- 稍后需要配置到后端的配置文件中。

### 2. 服务器 IP 白名单（有些接口会校验）

- 同一页面下，找到 **IP 白名单**，添加：
  - 你的后端服务器公网 IP（如：`1.2.3.4`）

### 3. 配置“网页授权域名”

**路径**：**设置与开发 → 公众号设置 → 功能设置**

- 网页授权域名：填写 **去掉协议和路径的域名**，例如：
  - `jobhub.cn`
- 根据微信提示：
  1. 下载一个类似 `MP_verify_xxx.txt` 的校验文件
  2. 上传到你网站根目录，使 `https://jobhub.cn/MP_verify_xxx.txt` 可访问
  3. 在后台点击“验证”

> ⚠️ **注意**：以后所有网页授权回调地址 **必须** 在 `https://jobhub.cn/...` 之下，不能用其它域名、不能是 IP。

## 三、后端对接设计（OAuth 授权 + 回调）

### 1. 后端配置（示意）

在 Spring Boot 中新增一个 wechat 配置，例如 `application-wechat.yml`：

```yaml
wechat:
  app-id: wx1234567890abcdef       # 公众号 AppID
  app-secret: your_app_secret_here # 公众号 AppSecret
  oauth-callback: https://jobhub.cn/api/auth/wechat/callback
```

Spring 里写个配置类读取这些属性（略）。

### 2. 设计用户表结构（建议）

在你自己的数据库中设计一张用户表，例如 `app_user`，至少包含：

- `id`（bigint，自增主键）
- `open_id`（公众号 openid，字符串）
- `union_id`（若未来接入开放平台/小程序，可统一身份，用于多端打通）
- `nickname`
- `avatar`
- `created_at` / `updated_at` 等

并在 `open_id` 上加唯一索引。

## 四、OAuth 流程（服务号网页授权）

### 1. 授权 URL 生成接口（后端）

新增一个接口：**返回微信授权 URL**，前端用它来跳转（H5）或生成二维码（PC）。

```java
@GetMapping("/auth/wechat/url")
public ResponseEntity<Map<String, String>> getWechatAuthUrl(
        @RequestParam(required = false, defaultValue = "/#/") String redirectPath) {

    String appId = wechatConfig.getAppId();
    String callback = wechatConfig.getOauthCallback();
    // 前端希望最终跳转到的 hash 路径，例如 "/#/" 或 "/#/progress"
    String state = URLEncoder.encode(redirectPath, StandardCharsets.UTF_8);

    String redirectUri = URLEncoder.encode(callback, StandardCharsets.UTF_8);
    // scope 选择 snsapi_userinfo，可拿到昵称头像；只要 openid 可用 snsapi_base
    String url = "https://open.weixin.qq.com/connect/oauth2/authorize"
            + "?appid=" + appId
            + "&redirect_uri=" + redirectUri
            + "&response_type=code"
            + "&scope=snsapi_userinfo"
            + "&state=" + state
            + "#wechat_redirect";

    return ResponseEntity.ok(Map.of("url", url));
}
```

> **说明**：
> - `redirectPath` 通过 state 传到回调里，回调结束后再跳回对应前端路由。
> - 真实环境建议把 state 做成随机字符串 + 存到 session 里，用于防 CSRF，这里为简化只演示携带路径。

### 2. 授权回调接口（后端）

配置的 `oauth-callback` 指向这里：`https://jobhub.cn/api/auth/wechat/callback`

核心流程：**code → access_token + openid →（可选 userinfo）→ 自己系统登录 → 设置 Session → redirect 回前端**

```java
@GetMapping("/auth/wechat/callback")
public void wechatCallback(
        @RequestParam("code") String code,
        @RequestParam(value = "state", required = false) String state,
        HttpServletResponse response,
        HttpSession session
) throws IOException {
    String appId = wechatConfig.getAppId();
    String secret = wechatConfig.getAppSecret();

    // 1. 用 code 换取 access_token 和 openid
    String tokenUrl = "https://api.weixin.qq.com/sns/oauth2/access_token"
            + "?appid=" + appId
            + "&secret=" + secret
            + "&code=" + code
            + "&grant_type=authorization_code";

    WechatTokenResp tokenResp = httpClient.get(tokenUrl, WechatTokenResp.class);
    if (tokenResp == null || tokenResp.getOpenid() == null) {
        // 可以重定向到错误页
        response.sendRedirect("https://jobhub.cn/#/login-error");
        return;
    }

    String openId = tokenResp.getOpenid();
    String accessToken = tokenResp.getAccess_token();
    String scope = tokenResp.getScope();

    // 2. 如需要昵称/头像，调用 sns/userinfo
    String nickname = "微信用户";
    String avatar = null;
    if (scope != null && scope.contains("snsapi_userinfo")) {
        String userInfoUrl = "https://api.weixin.qq.com/sns/userinfo"
                + "?access_token=" + accessToken
                + "&openid=" + openId
                + "&lang=zh_CN";
        WechatUserInfo userInfo = httpClient.get(userInfoUrl, WechatUserInfo.class);
        if (userInfo != null) {
            nickname = userInfo.getNickname();
            avatar = userInfo.getHeadimgurl();
        }
    }

    // 3. 在你自己的数据库中，按 openId 查找或创建用户
    AppUser user = userService.findOrCreateByOpenId(openId, nickname, avatar);

    // 4. 放入 Spring Session（你项目中已有 AuthService.SESSION_USER_ID）
    session.setAttribute(AuthService.SESSION_USER_ID, user.getId());

    // 5. 解析 state 中的前端目标路径
    String targetPath = "/#/";
    if (state != null && !state.isBlank()) {
        targetPath = URLDecoder.decode(state, StandardCharsets.UTF_8);
    }

    // 6. 重定向回前端
    response.sendRedirect("https://jobhub.cn" + targetPath);
}
```

> `WechatTokenResp` / `WechatUserInfo` 是你自定义的 DTO，字段包含 openid、access_token、scope、nickname、headimgurl 等即可。

## 五、前端接入（H5 + PC 扫码）

### 1. H5 场景（用户在微信里打开你的链接）

在前端 `App.tsx` 中，你已经有 `handleLogin`，可以改造成：

```typescript
import { apiFetch } from './services/apiClient';

const handleLogin = () => {
  (async () => {
    try {
      // 登录后回首页
      const res = await apiFetch<{ url: string }>('/auth/wechat/url?redirectPath=%2F%23%2F');
      window.location.href = res.url; // 跳转到微信授权页
    } catch (e: any) {
      alert(e?.body?.message || e?.message || '获取微信登录地址失败');
    }
  })();
};
```

- 当用户在 **微信内** 打开 `jobhub.cn` 并点击“微信登录”：
  - 页面跳转到微信的授权页
  - 用户点“确认登录”
  - 微信回调到 `/api/auth/wechat/callback`
  - 后端设置 session，并重定向回前端路由；前端再调用你已有的 `getCurrentUser()` 拉取用户信息。

### 2. PC 网页扫码场景（基于公众号网页授权）

**流程**：

1. PC 端打开 `https://jobhub.cn`，点击“微信登录”时：
   - 前端调用 `/auth/wechat/url?redirectPath=%2F%23%2Fprogress` 拿到授权 URL。
   - 把这个 URL 用二维码组件生成二维码。

2. 用户用手机微信扫这个二维码：
   - 微信在手机浏览器（或微信内 webview）打开授权页面
   - 用户确认后完成授权 → 回调到你的 `/api/auth/wechat/callback`
   - 后端登录成功，把 session 建好，跳转到 `https://jobhub.cn/#/progress`（在手机上）。

3. PC 端如何变成“已登录”？
   - **简单方案**：提示“请在手机端继续操作，登录后刷新本页即可查看状态”。
   - **进阶方案**：PC 端轮询一个 `/auth/current` 接口：
     - 在 PC 打开二维码时，生成一个 `loginTicket`，在 state 里携带；
     - 手机端授权完成后，后端根据 ticket 标记“某 ticket 已登录用户 X”；
     - PC 端轮询 `/auth/poll?ticket=xxx`，查到后，本地写 cookie / local token，刷新应用。这部分需要额外一套“临时票据”设计，这里就不展开了。

在你的现有体系下，先做**手机端内登录**是最简单、改动最小的方案；PC 扫码 + 票据轮询可以放到下一阶段。

## 六、安全细节和常见坑

### 1. state 防 CSRF

- 真实上线时，不要只把路径放进 state。
- **方案**：
  - 后端生成随机 `state`，写入 session 或 Redis；
  - 授权 URL 中携带这个 state；
  - 回调时先校验 state 是否匹配，再继续处理。
- 可以在 state 中编码一段 JSON，例如 `{"redirectPath":"/#/progress","nonce":"xxx"}`。

### 2. 错误处理

- code 只能使用一次，过期会报错，要做好异常提示；
- 微信接口有访问频率限制，注意不要频繁刷新 token。

### 3. 用户合并（unionid 设计）

- 如果未来还要接入 **开放平台扫码登录** 或 **小程序登录**，建议现在数据库就预留 `union_id` 字段；
- 当同一用户在不同端登录时，按 unionid 合并账号。

### 4. 测试环境

- 微信网页授权对域名限制比较严格，本地 `localhost` 或纯 IP 无法直接测试；
- 建议搭一个测试子域（如 `test.jobhub.cn`），备案后在公众号“网页授权域名”中配置它，专门用于联调。

## 七、落地建议总结

### 第一阶段（必做）

- ✅ 配置好服务号 + 域名 + 网页授权域名

## 附录：微信 API 参考

### 1. 获取 access_token

```
GET https://api.weixin.qq.com/sns/oauth2/access_token
?appid=APPID
&secret=SECRET
&code=CODE
&grant_type=authorization_code
```

**响应示例**：
```json
{
  "access_token": "ACCESS_TOKEN",
  "expires_in": 7200,
  "refresh_token": "REFRESH_TOKEN",
  "openid": "OPENID",
  "scope": "snsapi_userinfo"
}
```

### 2. 获取用户信息（需要 snsapi_userinfo）

```
GET https://api.weixin.qq.com/sns/userinfo
?access_token=ACCESS_TOKEN
&openid=OPENID
&lang=zh_CN
```

**响应示例**：
```json
{
  "openid": "OPENID",
  "nickname": "NICKNAME",
  "sex": 1,
  "province": "PROVINCE",
  "city": "CITY",
  "country": "COUNTRY",
  "headimgurl": "http://thirdwx.qlogo.cn/...",
  "privilege": []
}
```

### 3. 错误码参考

- `40029`: code 无效（已使用或过期）
- `40125`: 无效的 appsecret
- `40163`: code 已被使用

## 注意事项

1. **域名必须备案**：未备案域名无法配置网页授权
2. **HTTPS 必须**：回调地址必须是 HTTPS
3. **code 只能使用一次**：每次授权都会生成新的 code
4. **access_token 有效期**：通常 2 小时，需要时可使用 refresh_token 刷新
5. **频率限制**：注意微信 API 的调用频率限制，避免频繁请求
