## 二、数据模型设计

### 2.1 现有表变更

#### user_member
- 新增 **plan_id** 取值：`trial`（体验）、`1_month`、`3_month`、`lifetime`。
- 逻辑不变：以当前时间在 `[start_at, end_at]` 内判定是否 VIP；体验与付费会员共用同一表。

### 2.2 新增表

#### user_invitation（邀请关系）
| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 主键 |
| inviter_id | BIGINT | 邀请人 user_id |
| invitee_id | BIGINT | 被邀请人 user_id |
| reward_status | VARCHAR(32) | inviter_rewarded / invitee_rewarded / both |
| created_at | DATETIME | 创建时间 |

- 唯一约束：`(invitee_id)` 每人仅可作为被邀请人一次；或 `(inviter_id, invitee_id)`。
- 索引：`inviter_id`、`invitee_id`。

#### referral_code（内推码·VIP 可读）
| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | 主键 |
| company_name | VARCHAR(128) | 公司名称 |
| code | VARCHAR(128) | 内推码内容 |
| contributor_id | BIGINT NULL | 贡献者 user_id，可选 |
| usage_count | INT DEFAULT 0 | 使用次数 |
| is_valid | TINYINT(1) DEFAULT 1 | 是否有效 |
| created_at | DATETIME | 创建时间 |

- 索引：`company_name`、`is_valid`。

## 三、接口设计

### 3.1 方案9：免费试用 VIP

- **实现**：在 `AuthService.loginWithCode` 中，当 `createUser(openId)` 新建用户后，调用“开通体验会员”逻辑：向 `user_member` 插入一条 `plan_id='trial'`，`start_at=now()`，`end_at=now()+2天`。
- **无新增接口**。前端若需区分“体验会员”与“付费会员”，可由 `GET /api/auth/current` 在用户信息中增加 `isTrial: boolean`（或根据 `plan_id` 推断）。

### 3.2 方案7：会员权益可视化

- **后端**：`GET /api/auth/current` 或新增 `GET /api/vip/dashboard` 返回：
  - `savedQueryCount`：本月/累计“已节省查询次数”（可选，按需统计）；
  - `referralCodeCount`：内推码总数（供文案“XX 个热门公司内推码”）。
- **前端**：VIP 页展示权益列表与上述数据；可增加“已节省 XX 次查询”等文案。

### 3.3 方案6：内推码库

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/referral-codes | 分页列表，仅 VIP；Query: page, size, companyName(可选) |
| POST | /api/referral-codes/{id}/use | 记录使用（usage_count+1），仅 VIP |

- 非 VIP 调用返回 403。

### 3.4 方案3：邀请好友

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/invite/generate | 生成邀请码/邀请链接，返回 link + inviteCode |
| GET | /api/invite/stats | 当前用户邀请人数、已获得奖励说明 |

- **邀请注册**：被邀请人通过带 `inviteCode`（或 token）的链接注册；在 `AuthService.createUser` 完成后，根据 inviteCode 查 inviter，写 `user_invitation`，并给双方发“免费次数”或体验 VIP（见业务规则）。
- **业务规则**：邀请 1 人 → 双方各 +3 次免费查询（或写入 query_count 重置逻辑）；邀请 3 人 → 邀请者 5 天 VIP；邀请 10 人 → 邀请者 1 个月 VIP（具体奖励可配置）。

## 四、用户故事拆分

### US1：新用户获得 2 天 VIP 体验（方案9）
- **作为** 新注册用户，**我希望** 注册后自动获得 2 天 VIP 体验，**以便** 无限制查询并体验内推码等权益。
- **验收**：新用户登录后 isVip=true、vipExpiry=注册日+2；2 天后自动变为非 VIP。

### US2：会员页展示权益与价值数据（方案7）
- **作为** 用户，**我希望** 在会员页看到清晰权益说明和“已节省 XX 次查询”“XX 个内推码”等数据，**以便** 感知会员价值。
- **验收**：VIP 页展示权益列表；展示内推码数量（及可选：节省查询次数）。

### US3：VIP 可查看与使用内推码（方案6）
- **作为** VIP 用户，**我希望** 在单独页面查看内推码列表并可标记“已使用”，**以便** 投递时使用内推。
- **验收**：仅 VIP 可访问内推码接口与页面；非 VIP 见引导开通或 403。

### US4：用户可生成邀请链接并查看邀请统计（方案3）
- **作为** 已登录用户，**我希望** 生成邀请链接并查看已邀请人数与奖励说明，**以便** 邀请好友并获得奖励。
- **验收**：生成链接；被邀请人通过链接注册后，邀请关系落库，双方获得约定奖励（次数或 VIP）。

4. **方案3**：邀请表与生成/统计接口；注册时绑定邀请关系并发奖；前端邀请页。

每完成一个方案做接口测试与必要前端联调；发现 bug 即修。迭代结束输出《迭代 v1 纪要》。
